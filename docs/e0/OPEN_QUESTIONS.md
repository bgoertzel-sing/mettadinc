# Open questions for Ben (MeTTaDinC E0)

Each item is something in the plan that is ambiguous, inconsistent, or depends on material that isn't available. Page numbers refer to the Cetta implementation guide (printed page, with the PDF page in brackets), unless another document is named. Items 1 to 4 block or shape M0 and M1, so they come first.

1. **Do the bundle registry patches become part of the M0/M1 registry?** Entries 1–7 of M0's negative acceptance suite (§3.1, pp. 19–20 [PDF 20–21]; entry 1 begins on p. 19, entry 5 is on p. 20) use forms that exist only in the bundles' PROPOSED patches, not in `registry/mettadinc_registry.json`: `Keyed` and `View`, `Stream` (with `Population`, `Selection` and `Policy`), `Consumer`/`Accepts`, `Statistic`/`Store`, `CheckStatistic` and `CheckInterpretation`. Under M1's rule (unknown heads are InvalidInput) a base-registry implementation would return InvalidInput for the wrong reason, and the guide also says binding failures are InvalidInput "from M0 on". The options are: (a) adopt the ls, mg and wx patches into the registry as a coordinated change before M0 (my recommendation); (b) run those suite entries only once each patch is adopted, and leave them out of M0's acceptance until then.
2. **The clock-rate screen has no clear owner.** M2's deliverables include "the clock-rate screen" (p. 21 [PDF 22]). M3's negative gates require a sampled clock-rate screen whose suggested four-class encoding "must be refuted with behavioral defect one" (p. 22 [PDF 23]), and invariant regression case 3 cites F07. However, F07 (`ClockRates`) belongs to M7, is Unsupported in release 1, and `ClockRates` is not among the 24 first-release requests. Should the M3 gate test only the refutation of a given four-class encoding (that is `CheckBehavioral`, which is in release 1), with the screen itself deferred to M7?
3. **Seven first-release requests have no first-release claim as their outermost request:** `BehavioralTolerance`, `Bracket`, `PathClosure`, `Threshold`, `MeasureUpdates`, `CheckTrace` and `MeasureTrace`. `Bracket`, `PathClosure` and `Threshold` appear nested in `graded_closure.metta`. The only claims that use `CheckTrace` and `MeasureTrace` (O01–O04, and the seven-state chain) are on stochastic modules, which must answer Unsupported. `BehavioralTolerance` and `MeasureUpdates` appear in no fixture. Is a release-1 acceptance test needed for these (for example deterministic trace fixtures), or is "implemented but untested by the manifest" acceptable?
4. **The plan's own host baseline fails on a clean machine.** `make BUILD=core test-correctness test-profiles` (§2.1, p. 14 [PDF 15]) stops at `test-he-compat-catalog-guards`, which needs a Mettapedia Lean checkout (`METTAPEDIA_ROOT`). In the core lane, `test-petta-search-machine` fails one Python-namespace assertion that needs the Python build. Building also needs GMP headers (`libgmp-dev`), which the guide doesn't list. Which baseline should count as "green" for M0 entry: core with these two known exclusions, the Python lane, or a lane with Mettapedia available? Where is the Mettapedia repository? I did not look for it, because the order allows public sources only and doesn't name it. See CETTA.md for the counts.
5. **No decision-diagram package is pinned, but M3 is in the first release.** §2.5 (p. 17 [PDF 18]) requires a pin (CUDD, Sylvan or a small in-tree implementation) before M3 starts. Which one?
6. **Pins that later milestones need are unavailable:** the finite OmegaPLN reference interpreter and the MeTTaProN shared kernel IR (M4); CettaPacks (any specialized backend); MORK/PathMap snapshot interfaces beyond the pinned bridges, the ωPLN adapter target and the Hyperseed proof-plan registry (M7). The guide's CettaPacks reference is "design notes ... July 2026", which is not in the Drive folder. Are any of these published?
7. **Where does `CheckInterpretation` belong?** M0 item 4 says it "is built with the deterministic core in M2, once its registry patch is adopted", yet negative-suite entry 5 needs it Refuted. Until the mg patch is adopted, should entry 5 be Unsupported (the rule for later-milestone entries) or InvalidInput?
8. **Source-map details that differ from the pinned code** (CETTA.md has the line numbers). `grounded_dispatch_accepts_data_arg` is a `static` function in `src/eval.c:2309`, not in `grounded.[ch]`, so the held-syntax exception means editing `eval.c`. The guide calls `rhocalc` and `prime` "runtime profiles" (p. 14 [PDF 15]), but in 12da03b4 they are `--lang` languages; `--list-profiles` shows `he`, `he-compat`, `he-extended` and `he-prime`. Neither is a contradiction in substance, but the source map should be corrected before agents rely on it.
9. **Check counts in the package READMEs.** `01_language_specification/validation_package/README.txt` says the oracle makes "156 checks", but the oracle prints 157 and the folder README says 157. Examples 1 and 2 make 92 and 69 checks only when drat-trim and cake_lpr are installed (91 and 67 without them). Which tool set should the conformance baseline assume? I used the pinned tools; see ORACLES.md.
10. **The order's "two Google Docs".** I took these to be the two Docs in the Drive folder, *MeTTaDinC_executive_summary* and *MeTTaDinC_explainer*, because the order gives no other URLs. If you meant other Docs, please send their links.
11. **M0 and M2 overlap.** M0 lists E05, E08, E09, H08, H10, H12 and C01–C03, and M2 lists E01–E09 and H01–H12 again. MILESTONES.md counts each claim at its first milestone. Is that the intended reading, with M0 delivering a subset and M2 the full set?
12. **Negative gates without fixtures.** Many gates name no fixture, for example "a candidate partition that is stable but not coarsest" (M2), "a proof log for a different formula" (M3), "negative masses, wrong row sums, float probabilities" (M4), "a host result bag used as a law without a scheduler" (M5) and "filling an unmeasured correspondence with zero" (M6). §3.9 says to build them as `tests/dcalc/mutations/`. Should fixture authoring be a separate task before each milestone, or part of it? MILESTONES.md marks every such gate as "fixture: none named".
