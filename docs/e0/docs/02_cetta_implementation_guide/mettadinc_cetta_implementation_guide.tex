\section*{Purpose and use}
This document hands the implementation of MeTTaDinC to coding agents. It accompanies the language
specification of the same date \cite{spec}, which is normative for every semantic claim, and the
validation package, which is normative for every interface: the registry file
\code{registry/mettadinc\_registry.json}, the fixture modules in \code{fixtures/}, the claims manifest
file \code{manifest.json}, the oracle \code{oracle/verify\_mettadinc.py} with its results, the static
checker \code{check\_fixtures.py}, and the pinned versions in \code{DEPENDENCIES.json}. Here are the
invariants an implementation must keep, the intermediate representation and backends, the default
algorithms and their scope, the certificate formats and their replay, the trusted boundary of the
symbolic path, the extension points of Cetta at a pinned revision, and a sequence of milestones whose
acceptance is stated in manifest claims.

The order of work is: build a small implementation whose certificate boundaries are strict, so that
every result is bound to the objects it is about and every status means one thing; generate the full
frontend from the registry and load the fixtures; implement the graded deterministic core on tables;
add the symbolic backend with its obligation generator and proof pipeline so that the forty-bit
fixtures pass without enumeration and the adversarial candidate is rejected; establish independent
replay and differential validation; then add stochastic dynamics and linear realizations,
nondeterminism and simulation, the composition kernel with both kinds of hive, and the Hyperseed,
discovery and integration libraries. A release whose scope is small but exact is useful. The
examples already exercise more forms than a first implementation can make reliable, which is why the
work starts with the certificate boundaries.

\subsection*{Coding-agent entry checklist}
\begin{enumerate}
\item Read the specification, this guide and the package README of the same date. Run
\code{python3 oracle/verify\_mettadinc.py} and \code{python3 check\_fixtures.py}; both must succeed
before any work starts, and both must still succeed when it ends.
\item Record the Cetta revision and read the repository's build and contribution instructions before
editing. Record the registry digest you build against.
\item Identify your milestone, its manifest claims, owned files, shared IR interfaces and required
negative cases. A change to the registry, a certificate format or canonical serialization is a
coordinated change: it updates the registry, the fixtures, the manifest and the checker together, and
dependent work waits for it.
\item Implement the smallest complete path from source through admission, execution and replay. Never
hard-code fixture answers, and never resolve an interface question from a PDF listing when the
registry or a fixture answers it.
\item Keep the negative acceptance suite of Section~\ref{sec:negative} passing at every step: each of its
fixtures is a small change that must make a successful result fail with a precise status.
\item Return reproducible commands, structured results, replay evidence, resource records, the
manifest claims covered and the remaining unsupported surface. Performance claims need measurements
with unchanged semantics and arithmetic.
\end{enumerate}

\section{Implementation contract}\label{sec:contract}

\subsection{Authority and scope}

The specification is authoritative for semantics and the registry for interfaces. When an example,
an optimization or a host convenience conflicts with either, keep the semantics and the registry and
report the conflict. Never weaken a claim to make a fixture pass. No MeTTaDinC implementation exists
yet. The target is a reflective MeTTa sublanguage hosted first in Cetta, with a portable semantic
core that does not depend on a particular evaluator's rewrite order. Unrestricted MeTTa evaluation,
neural training, global probabilistic inference, a general theorem prover and the whole of Hyperseed
are outside the first release.

\subsection{Semantic invariants}\label{sec:invariants}

Types and result schemas must keep the following distinctions visible.
\begin{enumerate}
\item Claim kinds are distinct types: current adequacy, update compatibility, behavioral
(bisimulation) adequacy, trace adequacy, simulation, exact induction, approximate induction and
linear realization. Evidence for one never satisfies a consumer of another without a registered
theorem; in particular a positive behavioral defect does not refute trace equality.
\item Observation equality is \code{Literal} or \code{Observer}. A zero current defect under a
non-separated value tolerance yields decoders into the zero-distance quotient only, and the result
says so.
\item A measurement (\code{Measure*}, \code{Defects}) is Checked when its interval is computed to the
requested precision, whatever the value. A check (\code{Check*}) compares the interval with
\code{Within}, whose default is $0$. \code{Output} projects only from Checked results.
\item \code{InduceExact} requires current adequacy and update compatibility with defect zero, and
literal congruence of the code fibers, checked on code values whatever the code tolerance (claims
C01--C03); it returns a quotient arrow. \code{InduceApprox} returns a representative machine, its
section (default \code{Center}), radius, arrow defect and a priori bound.
\item The horizon \code{(Steps h)} covers the initial observation and $h$ transitions; its tolerance is
$\Phi^{h+1}(1)$.
\item A transition law, a tolerance, a checked transfer and a host result bag are different types. A
bag becomes a set, multiset or law only under the interpretation the interface declares; a transfer
becomes a kernel only through the registered \code{KernelOf} construction.
\item Arrow kinds have distinct types and registered composition laws: functions for quotient arrows
and homomorphisms, additive defects for graded arrows and transfers, $(\lambda_L\lambda_K,
\rho_L\lambda_K+\lambda_L\rho_K)$ for linear arrows, $(L_2L_1,L_2\eta_1+\eta_2)$ for affine contracts.
Composing across kinds without a registered conversion is InvalidInput.
\item A signed linear realization is not a machine. A replayed positive candidate bounds the positive
dimension from above only.
\item Kernel hives and transfer hives are different types with different coherence claims.
\item A symbolic carrier is admitted only with its obligations discharged; type-checking its terms is
not admission.
\item A prior-dependent averaged model is an aggregate, not a quotient.
\item Probabilities, tolerances and defects, p-bit pairs, report availability, error bounds, operator
norms and costs never convert implicitly; an estimate becomes PLN evidence only by a conversion that
preserves its estimand and dependence assumptions (Section~\ref{sec:estimates}).
\item Exact claims are about admitted models; population claims need their own evidence and status.
\item Shared and fresh reads of random or nondeterministic variables are declared, never inferred.
\item Unmeasured correspondences in a hive are marked, never filled with zero.
\item Every result carries its binding: module digest and subject names, source and target model
identities, the checked interface with its value tolerances, and its scope (initial states,
reachable-state scope, horizon, discount, policy class). Every operation that consumes a result
validates the binding first, and a mismatch is InvalidInput naming the field, in every release.
\item One assurance policy assigns every status: Checked only on the grounds \code{Exact} and
\code{Replayed}, Refuted only on a replayed \code{Witness}, Conditional on
\code{(TrustedBackend solver version logic obligation-digest)} for an unreplayed backend answer, with
\code{agreed\_by} recorded as evidence, on \code{(Assumption name digest)} for an assumption the
source declares, and on \code{(EstimatedPremise result-digest delta)} for a premise that is an
estimate; derived results inherit the union of their premises' assumptions, and consumers accept
only what their \code{Accepts} declaration lists.
\item A distance value enters a result only through the registered certificate kinds, whatever
algorithm computed it, and an exact measurement needs a lower and an upper certificate that meet;
when the distance is a supremum that no registered certificate attains, the answer is Unknown with
the interval. Trace-event and policy-tree tests are undiscounted probabilities and bound a behavioral
distance at discount one only. On a stochastic machine a trace refutation over observation-based
policies needs a policy tree; a word witness never certifies it.
\end{enumerate}
Five regression cases protect these invariants from the start, each with its manifest claims. First,
states $0,1,2$ with constant observations, encoding $\{0,1\}\,|\,\{2\}$ and update $0\mapsto0$,
$1\mapsto2$, $2\mapsto2$: the behavioral defect is zero while the update defect is one (H09, H10).
Second, the posterior summary of the receipt memory: it is not compatible with the union merge, and a
merge of posteriors as independent evidence double counts shared receipts (P10--P13). Third, the
forty-bit zero machine: a sampled relevance screen drops the tail bits, and the resulting four-class
encoding has behavioral defect one (F07). Fourth, the adversarial zero-tail candidate, which passes
every local check and fails coverage (F05). Fifth, for the first stochastic milestone, the
seven-state chain, where the behavioral check is refuted by a modal test while the trace check passes
(S03, S05).

\subsection{Registry-driven handoff}\label{sec:registry}

The registry fixes, for every declaration head, its positional arguments, fields, field kinds and
which fields are required or repeatable; for every request, its library, positional arguments,
keyed arguments with kinds and defaults, result type, statuses beyond the base statuses, supported
dynamics and carrier backends, and the dynamics it supports in the first release; for every result
type, its fields; and the first-release capability manifest. Build the frontend from it:
\begin{itemize}
\item generate, or drive from tables, the declaration parser, the argument checker and the result
schemas, so that a registry change propagates mechanically;
\item give every request the base statuses Conditional, Unknown, Unsupported and InvalidInput in
addition to its registered ones;
\item apply registered defaults at admission and record them in the claim, so that
\code{(CheckBehavioral R)} and \code{(CheckBehavioral R (Within 0)} \code{(Discount 1) (Horizon AllFiniteWords))}
have the same identity;
\item answer Unsupported, never InvalidInput, for a well-formed request outside the running release's
manifest whose premises pass the binding rules, and InvalidInput for a malformed request or one whose
premises fail them;
\item treat a method declared in a module as a request whose result type is its declared
\code{Returns} type, which must equal the result type of its body's final request.
\end{itemize}
The checker \code{check\_fixtures.py} is the reference reading of the registry for static questions:
an implementation's admission must accept every fixture module it accepts and reject the mutations
it rejects (Section~\ref{sec:golden}).

{\raggedright
The first-release manifest covers deterministic dynamics, crisp and \L{}ukasiewicz values, enumerated
and symbolic carriers with the \code{BitVectors} primitives, the core requests and the
\code{GradedKernels} library:
\code{BehavioralTolerance}, \code{Bracket}, \code{CheckAbstractionMap}, \code{CheckBehavioral}, \code{CheckBlockPartition}, \code{CheckNow}, \code{CheckTrace}, \code{CheckTransitive}, \code{CheckUpdates}, \code{Defects}, \code{Delta}, \code{InduceApprox}, \code{InduceExact}, \code{MeasureBehavioral}, \code{MeasureNow}, \code{MeasureTrace}, \code{MeasureUpdates}, \code{MinimizeForQueries}, \code{PathClosure}, \code{Refine}, \code{SamePartition}, \code{Then}, \code{Threshold}, \code{WeakestWithin} (24 requests, generated from the registry).\par}

dense state identifiers cannot later carry symbolic maps, so dense identifiers belong to the table
backend only.

\subsection{Results, projections and status rules}

Every result uses the envelope of the specification, with \code{Value} fields fixed by the request's
registered result type. A user-authored atom headed \code{Checked} is data. \code{(Output R Value)}
returns the whole payload and \code{(Output R F)} a registered top-level field, where \code{R} is a
derivation name or a result variable bound by \code{LetResult}; projection from a result that is not
Checked yields a dependency diagnostic. Claims, bindings, scopes and defect intervals serialize as
\begin{lstlisting}
(Claim (Kind Behavioral) (Within 0) (Equality Literal))
(Binding (Module "sha256:...") (Subject PosteriorOnly) (Machine Memory)
         (Interface (Digest "...")))
(Scope (Init (All)) (States (All)) (Horizon AllFiniteWords) (Discount 1))
(Defect (Lower (Rat 3 20) (Certificate (WordWitness ...)))
        (Upper (Rat 3 20) (Certificate (Prefixpoint ...))))
(Assumptions) (Assurance Replayed)
\end{lstlisting}
A result whose verdict came from an SMT solver without a replayed proof carries instead
\code{(Assumptions (TrustedBackend cvc5 1.4.2 QF\_LRA "sha256:..."))}, its evidence lists any
agreeing backend under \code{agreed\_by}, and its status is Conditional.
A measurement with \code{(Precision p)} is Checked when $u-\ell\le p$ and Unknown otherwise. A check
with bound $e$ is Checked when $u\le e$, Refuted when $\ell>e$ with the lower-bound certificate as
\code{Witness}, and Unknown otherwise. A malformed probability row is InvalidInput, never a refutation;
an interrupted implemented search is Unknown; an operation outside the manifest is Unsupported; a
failed prerequisite produces a dependency diagnostic naming it.

Replay assigns statuses by the assurance policy of the specification: a validated certificate gives
Checked with assurance \code{Replayed}, an exact computation of the core gives \code{Exact}, a replayed
counterexample gives Refuted with \code{Witness}, and a backend answer without replay gives
Conditional. Agreement of a second backend is evidence and never upgrades a Conditional result; only
a replayed proof discharges a \code{TrustedBackend} assumption, after which the dependent derivations
are evaluated again. A witness alone does not prove shortestness; when a shortest witness is
claimed, the certificate also carries the minimal separating sequence from the splitting tree.
Stability alone does not prove
coarseness; the splitting tree or formula graph does. A proof log certifies only the formula it was
produced for, so the replay checker regenerates the formula from the frozen model with the pinned
obligation generator and compares it byte for byte before checking the log.

\subsection{Symbolic admission, the obligation generator and the proof pipeline}\label{sec:proofs}

\emph{Obligations.} For a carrier predicate $C$, block predicates $B_i$, representatives $r_i$ and a
successor map $\sigma$, a symbolic partition certificate needs coverage
($C\Rightarrow\bigvee_iB_i$), disjointness ($C\Rightarrow\neg(B_i\wedge B_j)$), membership
($C(r_i)\wedge B_i(r_i)$), constancy of every query on every block, stability
($C\wedge B_i\Rightarrow B_{\sigma(i,a)}\circ T_a$), and, for symbolic maps, totality and
exclusivity of cases and closure ($C\Rightarrow C\circ T_a$). For a reachability scope, universal
obligations are proved on an inductive invariant (contains the initial states, closed under the
actions), and existential ones---membership, nonemptiness---need reachability words. An IR node that
guarantees an obligation by construction, such as the fibers of a total key function, cites the rule
in the certificate instead of a proof. The adversarial candidate of fixture
\code{forty\_bits.metta} must be refuted on coverage with witness word $4$ (claim F05); the same blocks
on \code{Reach(0)} must be accepted (F06).

\emph{The obligation generator is trusted.} It translates admitted terms and the frozen semantics of
the registered primitives into CNF. Keep it small and separate from the solvers: one documented
encoding per primitive (\code{BitAt}, \code{SwapBits}, \code{RotateRange}, \code{SetBit},
\code{Xor}, \code{Parity}, \code{Slice}, \code{IsZero}, the Boolean connectives), Tseitin
definitions with a deterministic variable order, and a deterministic clause order so that the same
obligation always yields the same bytes. Version it with the registry and record its version and the
CNF digest in every certificate. Test it by translation validation: for widths $3$ to $12$ of every
symbolic fixture, decide each obligation both by enumeration and by the generated CNF, and require
agreement, including on the mutations. A verified generator is future work; until then this test
set is part of the trusted computing base's evidence.

\subsection{Default algorithms and their scope}\label{sec:algorithms}

With $n$ states, $m$ transitions and exact arithmetic costs counted separately:
\begin{itemize}
\item \emph{Crisp current and update checks}, those of a representation whose code tolerance is the
discrete equality, are functional-dependency tests---does the code determine each query, does it
determine each successor's code---implemented as hash group-bys with exact comparison, linear in $n$
plus $m$. Under a two-valued metric code tolerance the same group-bys run on the classes of the
tolerance, and \code{InduceExact} adds the literal-congruence group-by on the code values.
\item \emph{Behavioral partition}: Hopcroft or Paige--Tarjan refinement in $O(m\log n)$
\cite{hopcroft,paigetarjan}; for deterministic machines, a splitting tree with minimal separating
sequences \cite{smetsers}; for other functors, characteristic formulas in shared form
\cite{explaining}.
\item \emph{Crisp behavioral check}: compute $\Pbeh$, then test the dependency ``code determines
behavioral class''. A failing group yields a witness pair, separated by the test at their lowest
common ancestor. The pair-graph search of the specification's definitions is the reference engine
only; it needs $\Theta(n^2)$ memory.
\item \emph{Stochastic lumping} in $O(m\log n)$ \cite{valmari,derisavi}, with exact sums over explicit
nonzero entries.
\item \emph{Graded distances}: for deterministic machines, shortest paths in the pair graph restricted
to the pairs a request needs; for labelled Markov chains with one transition function, exact
polynomial-time computation, with policy iteration or on-the-fly algorithms in practice
\cite{chenvbw,tangvb,bacci}; for several actions, exact value iteration for lower bounds and couplings
for upper bounds, reported as an interval with no complexity claim.
\item \emph{Trace equivalence and linear realizations}: Krylov iteration over the alphabet of
action--observation letters with fraction-free elimination \cite{tzeng,kiefer}; quantitative trace
discrepancy by exact enumeration through a declared horizon, or as an interval bounded above by a
behavioral certificate at discount one.
\item \emph{Nondeterminism}: bisimulation by relational refinement, simulation preorders in $O(mn)$
\cite{hhk}, distinguishing formulas as in \cite{explaining}.
\item \emph{Symbolic refinement}: signature refinement over decision diagrams as in Sigref and Storm
\cite{sigref,storm}, preceded by a cone-of-influence pass and, when declared, reachability.
\item \emph{Closure}: max--\L{}ukasiewicz Floyd--Warshall in $O(n^3)$.
\item \emph{Frontier search}: exhaustive over partitions for small carriers; heuristic otherwise, with
optimality reported Unknown.
\end{itemize}
Hash collisions are resolved by exact comparison. Rationals are canonical (positive denominator,
reduced, normalized zero); finite-field values are reduced modulo the declared prime.

An algorithm that computes a distance exactly still has to hand replay a certificate for each end of
the interval. Value iteration from zero yields horizon distances, which are lower bounds certified
by tests of the same depth, and over all finite words they can approach the distance without
reaching it (claim U01). At discount below one, the optimal dual potentials of the Kantorovich
programs at the computed fixed point give a \code{DualPostfixpoint} that closes the interval (U04);
at discount one no lower
certificate other than tests is registered, so a Precision-0 request whose tests stop short of the
upper certificate returns Unknown with the interval, even on a chain with one transition function
where the polynomial-time algorithms find the value. Through a declared horizon, a
\code{LayeredPrefixpoint} gives the matching upper bound (U02). Over observation-based policies the
trace defect through a horizon is computed by enumerating deterministic policy trees, which suffice
because a randomized policy separates no more; a maximizing tree, with the event on which the two
laws differ most, is the \code{PolicyTreeWitness} (O03, O04). Literal congruence is one more
group-by: the code value of each state determines the code values of its successors.

\subsection{Resources and incrementality}\label{sec:resources}

Every budget names its units: pair expansions, signature computations, decision-diagram nodes, SAT
conflicts, LP pivots, arithmetic bit operations, wall time or memory. A horizon is part of a claim and
a budget is not; exhausting a budget yields Unknown with a record of completed work. Host evaluation
fuel is never a horizon.

Certificates are cached by the semantic digests of their dependencies. Interface changes reuse them
only through the transport rules of the specification, which distinguish universal upper bounds,
witnesses, exact values, optimality claims and measure-dependent results; each reuse is recorded as a
derivation step citing its rule, and the step validates the certificate's binding first. No rule
moves a certificate to another machine, simulation target, stream or snapshot. A result bound to a
view keeps the view's queries when the item machine gains a query, and gives the new query's
consumer no coverage. Adding a query resumes refinement from $\Pbeh\cap\ker o$; adding an
action resumes from $\Pbeh$; removing queries or actions transports upper bounds and downgrades
coarseness to sufficiency. Restricting to a forward-closed subset transports upper bounds, keeps a
witness only if its pair lies in the subset, and recomputes exact values, optimality and
measure-dependent results (claims H03, H04). Recompiling a module changes its artifact digest, not its
semantic digest, and invalidates nothing.

\subsection{Estimates and their conversions}\label{sec:estimates}

An Estimated result carries, in the envelope's \code{Estimate} field, its estimand, estimator,
sampling protocol, sample size, error bound, failure probability, dependence assumptions and
combination rule, and also its population (the units
the stream samples), its selection rule (which units become rows, and when), the digest of the
policy version under which the rows were produced, and the estimand as a function of that
population. Reuse under another policy version needs a declared transport argument, for instance
pointwise monotone labels on a fixed population, or a new estimate; a selection rule that depends on
the policy blocks transport. A stream whose declared digest does not match its file is InvalidInput
before any count is taken. A result derived from an estimate keeps the \code{Estimate} field and is
Conditional on \code{(EstimatedPremise result-digest delta)}, so only a consumer that accepts
Estimated results can use it. The $\omega$PLN adapter converts an
estimate to evidence counts only when it is a proportion over independent observations of the same
estimand; a U-statistic of order two converts to an interval truth value, or to counts of effective
size $\lfloor n/2\rfloor$ for a Hoeffding-type consumer; an anytime-valid or sequentially selected
estimate converts to an interval truth value at its stopping time and never to counts; an estimate from
dependent samples carries its dependence assumptions. Converting an Estimated result into an exact
channel is a negative gate.

\subsection{Admission}

Implement source admission before any domain algorithm. It consumes held syntax, resolves a complete
\code{DC.Module}, and returns an immutable admitted module or a structured failure; \code{dc.run} is a
wrapper around it. A proposed private entry is \code{\_\_cetta\_lib\_dcalc\_admit}. Establish raw-data
treatment of its arguments through \code{grounded\_dispatch\_accepts\_data\_arg} or an equivalent typed
holding wrapper, without broadening data treatment for other native operations and without adding the
service to the type-pure list.

The first admission tests install hostile host equations for names such as \code{Map}, \code{Body} and a
module-local function, and a held expression containing an I/O or state-mutating operator. Loading the
module must execute none of them. Phases, in order:
\begin{enumerate}
\item parse with source locations, collecting declarations without executing embedded requests;
\item check every declaration and request against the registry: heads, fields, argument kinds,
required arguments, defaults; assign module-local identifiers; reject duplicates and unknown
references, and never resolve a name against the surrounding space;
\item check the profile coordinates against the capability manifest and the effect and type
signatures of imported primitives;
\item check binders, expression types and dependency edges: linear case patterns, one lexical
argument per \code{Body}, an acyclic map-call graph, no derivation cycles;
\item resolve carrier elements at their element types (symbols in symbol-typed carriers, constants
otherwise) and reject duplicates under typed equality; compute separation of each value tolerance;
\item for enumerated carriers, materialize maps and kernels, rejecting missing or overlapping cases
(even agreeing ones), out-of-carrier values, invalid rationals, unnormalized rows and floating-point
literals in exact positions; for symbolic carriers, discharge totality, exclusivity and closure
through the obligation generator and the proof pipeline, or by a cited construction rule;
\item freeze the IR and its digest, and execute requests against that snapshot.
\end{enumerate}
Never apply host nondeterministic rewriting to a deterministic map. Two host alternatives are neither
a law nor a legal map; a nondeterministic map is admitted only through \code{Choice} with a declared
bag interpretation.

\subsection{Ownership and persistence}

Cetta atoms are arena-allocated with recorded arena identities and reset epochs. Never keep a
borrowed pointer from a request's scratch arena in a retained module, cache entry or certificate;
copy semantic values into storage whose lifetime covers every consumer, including transitive
children. Native resources (decision-diagram managers, solver instances) have one owner and a
destructor, and admission defines what happens when a handle closes or a session ends. Three
identities stay separate: the semantic module digest, the compiled artifact digest and the runtime
handle. Shared admitted modules are immutable; scratch state is thread-local or follows the host's
concurrency protocol. Cancellation releases temporary resources and yields Unknown with the work
completed.

\subsection{Reference path, specialized paths and replay}

Build a transparent reference engine before specialized execution: it enumerates the definitions
directly---pair graphs, signature refinement, dense lifts---and serves small fixtures and differential
tests. Specialized backends must produce semantically comparable results. Replay is not a second run
of the optimized routine; it checks equations, couplings, matchings, proof logs, tests, formula graphs
and splitting trees against the frozen model. Statuses never collapse: a malformed row is InvalidInput,
a valid row exposing a conflict is Refuted, completed exhaustive search supports Checked within its
scope, resource exhaustion is Unknown, and an empirical audit is Estimated even when its arithmetic is
exact.

\section{Milestones, fixtures and acceptance evidence}\label{sec:milestones}

Milestones describe capability and evidence, not calendar time. The first useful release is
M0--M3: strict certificate boundaries, the full frontend, the graded deterministic core and the
symbolic backend. Each work package ends with the manifest claims it covers, reproducible commands, structured
results, negative cases, a replay run and a statement of the remaining unsupported surface. A claim
is covered when the implementation returns its required status and values with replayable evidence;
claims outside the running release must return Unsupported.

\subsection{M0: strict certificate boundaries}\label{sec:negative}

The first milestone is a small implementation whose certificate boundaries are strict. It answers
few requests, and it keeps its guarantees under small adversarial changes of its inputs: a premise
about the wrong machine, a stream whose content changed, a verdict that rests on a solver answer
nobody replayed, a code tolerance that hides a literal failure. The fixtures of the package and of
the application bundles already exercise more forms than a first implementation can make reliable,
so M0 makes the boundaries strict before any breadth is added. Every later milestone keeps them, and
keeps the suite below passing.

M0 delivers one mechanism for each boundary, or fixes its interface where a later milestone builds
it.
\begin{enumerate}
\item Every certificate is bound to its exact interface. The result envelope carries the binding of
the specification's trust model: module digest and subject names, source and target model
identities, the checked interface with its value tolerances, and the scope with initial states,
reachable-state scope, horizon, discount and policy class. One validation routine runs before any
consuming operation uses a premise: \code{Then} and transfer composition, safety transfer along a
simulation, lifting to a keyed store, rebuilds, stream and snapshot reads, and gates. The registry's
binding rules run at admission, so a mismatch is InvalidInput naming the field in every release,
also for a request that is otherwise Unsupported, and wrong-store lifting and wrong-target safety
transfer are rejected before any proof transfer begins.
\item One assurance policy assigns every status, on the grounds of the registry's \code{assurance}
entry. Conditional results carry their \code{TrustedBackend} assumptions and their
\code{agreed\_by} evidence to every consumer, derivations take the union of their premises'
assumptions, the declarations \code{(Accepts Checked)} and
\code{(Accepts Checked (Conditional (TrustedBackend cvc5)))} are enforced, and a gate counts a
Conditional result that its consumer does not accept as inadequate coverage. Results supported by a
solver, results replayed independently and empirical estimates stay distinguishable all the way to
the consumer.
\item Obligations are built from the admitted source. M0 fixes the obligation generator's interface:
its only input is the admitted IR, and every obligation it emits records the digest of that source,
so no separately written model of a module stands between the source and its proof obligations;
the independent mathematical models of the examples stay as differential checks. It also builds the
mutation harness, which edits admitted sources to restore known bugs and requires each affected
verdict to change. The generator itself is built in M3, with the symbolic backend, and the
access-policy mutation becomes a gate there.
\item Preserving a goal's meaning is an explicit obligation. M0 fixes the result types and the rule:
informational refinement and informational equivalence, the one-way and two-way adequacy checks
between goal observers, are results under those names, and preservation of the meaning is a
separate obligation with declared, protected decoders,
$d_{\mathrm{new}}(g_{\mathrm{new}}(x))=d_{\mathrm{old}}(g_{\mathrm{old}}(x))$ for every valid record $x$;
a goal change counts as a renaming only when both hold. The adequacy checks are the
\code{CheckNow} requests of M0. The interpretation request, \code{CheckInterpretation} of the Omega
memory and goals guide, is built with the deterministic core in M2, once its registry patch is
adopted.
\item Empirical claims name their populations and selection rules. The envelope's \code{Estimate}
field carries the population, the selection rule, the policy version and the estimand, and a result
derived from an estimate is Conditional on it; M0 fixes these records, and the estimators come in
M4. A policy change triggers a
transport check, which passes only with a declared argument, or a new estimation task; a selection
rule that depends on the policy blocks transport.
\item The witness forms and induction preconditions are fixed before the compiler's interfaces
harden: the literal-congruence obligation of \code{InduceExact} with its
\code{CongruenceWitness}; the \code{PolicyTreeWitness} format with its admissibility check, and
Unsupported answers for policy-class trace requests until its replay exists; and the distance
certificates of Section~\ref{sec:replay}, with Unknown for a Precision-0 measurement whose
certificates do not meet.
\end{enumerate}
On the computational side M0 covers the core requests these boundaries touch, on enumerated
deterministic modules: \code{MeasureNow}, \code{CheckNow}, \code{CheckUpdates}, \code{InduceExact},
\code{CheckAbstractionMap} and \code{Then}, with the manifest claims E05, E08, E09, H08, H10, H12 and
C01--C03. Every other request returns Unsupported or, when a binding rule fails, InvalidInput.

The negative acceptance suite is M0's acceptance. Each entry names the document whose bundle holds
the fixture and the status an implementation must return. An entry whose request needs a later
milestone is answered Unsupported until that milestone, except that binding failures are
InvalidInput from M0 on; from its milestone on it must return the status given.
\begin{enumerate}
\item An index of the live-memory guide \cite{livememory} declared with the item statistic of a
machine that has fewer queries than the store's item machine, as in
\code{(Keyed EngineAsItems (Of Items) (Item EngineStat))} where \code{EngineStat} is a statistic of

round-trips and stale dependencies separately from mathematical obligations.

\subsection{Handoff and definition of done}

Each handoff names the specification date, the registry digest, the Cetta commit, the profile
coordinates, owned files, dependencies and the manifest claims covered. A completed package includes:
\begin{enumerate}
\item implemented source forms and request signatures, with unsupported forms listed;
\item the manifest claims covered, with their structured results and replay evidence;
\item a build record with toolchain and dependency versions, matching \code{DEPENDENCIES.json};
\item correctness, negative, translation-validation and replay results;
\item unresolved assumptions and host limitations;
\item a short account of changed behavior and its evidence.
\end{enumerate}
Proposed targets, absent from unmodified Cetta until implemented:
\begin{lstlisting}
make test-dcalc-boundaries   # M0 negative acceptance suite and binding rules
make test-dcalc-registry     # check_fixtures.py and admission parity (M1)
make test-dcalc-core         # M0-M2 manifest claims
make test-dcalc-symbolic     # M3 claims and the adversarial candidate
make test-dcalc-obligations  # translation validation of the generator
make test-dcalc-proofs       # cadical -> drat-trim -> cake_lpr on all obligations
make test-dcalc-stochastic   # M4
make test-dcalc-nondet       # M5
make test-dcalc-compose      # M6
make test-dcalc-hyperseed    # M7
make test-dcalc-replay       # replay checker against golden and mutation sets
make test-dcalc-oracle       # run the oracle and compare with the manifest
make bench-dcalc
\end{lstlisting}
Performance work follows semantic acceptance and reports state or description size, action and
query counts, nonzero transitions, arithmetic sizes, decision-diagram sizes, proof-log sizes and
memory. A speedup obtained by weakening scope, dropping multiplicities, replacing exact laws by
floats or skipping replay is a different experiment and is labelled as one.
