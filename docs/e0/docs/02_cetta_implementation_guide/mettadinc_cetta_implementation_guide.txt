First release. Strict certificate boundaries first: results bound to the exact objects they are about, one
assurance policy for every status, obligations generated from the admitted source. Then a held-syntax
frontend driven by the registry; a term-level typed IR; the graded deterministic core with its crisp special
case, on an enumerated table backend and a symbolic backend with an explicit admission contract;
measured and checked defects with two-sided certificates, splitting trees and proof-logged obligations,
all replayed by an independent checker; certificate transport across interface changes. Acceptance: the
negative acceptance suite, the 45 first-release claims of the manifest, and Unsupported for the other 78.
Implementation discipline. Generate interfaces from the registry instead of reading them off the PDF.
Preserve the specified claim kind and scope through parsing, interpretation, compilation, serialization
and optimization. Use the efficient classical algorithms within their proved scope. Report unsupported
capability as Unsupported.

Purpose and use
This document hands the implementation of MeTTaDinC to coding agents. It accompa-
nies the language specification of the same date [1], which is normative for every semantic
claim, and the validation package, which is normative for every interface: the registry file
registry/mettadinc_registry.json, the fixture modules in fixtures/, the claims mani-
fest file manifest.json, the oracle oracle/verify_mettadinc.py with its results, the static
checker check_fixtures.py, and the pinned versions in DEPENDENCIES.json. Here are the
invariants an implementation must keep, the intermediate representation and backends, the
default algorithms and their scope, the certificate formats and their replay, the trusted boundary
of the symbolic path, the extension points of Cetta at a pinned revision, and a sequence of
milestones whose acceptance is stated in manifest claims.
    The order of work is: build a small implementation whose certificate boundaries are strict, so
that every result is bound to the objects it is about and every status means one thing; generate
the full frontend from the registry and load the fixtures; implement the graded deterministic
core on tables; add the symbolic backend with its obligation generator and proof pipeline so
that the forty-bit fixtures pass without enumeration and the adversarial candidate is rejected;
establish independent replay and differential validation; then add stochastic dynamics and linear
realizations, nondeterminism and simulation, the composition kernel with both kinds of hive,
and the Hyperseed, discovery and integration libraries. A release whose scope is small but exact
is useful. The examples already exercise more forms than a first implementation can make
reliable, which is why the work starts with the certificate boundaries.

Coding-agent entry checklist
  1. Read the specification, this guide and the package README of the same date. Run
     python3 oracle/verify_mettadinc.py and python3 check_fixtures.py; both must
     succeed before any work starts, and both must still succeed when it ends.
  2. Record the Cetta revision and read the repository’s build and contribution instructions
     before editing. Record the registry digest you build against.
  3. Identify your milestone, its manifest claims, owned files, shared IR interfaces and required
     negative cases. A change to the registry, a certificate format or canonical serialization is a
     coordinated change: it updates the registry, the fixtures, the manifest and the checker
     together, and dependent work waits for it.
  4. Implement the smallest complete path from source through admission, execution and
     replay. Never hard-code fixture answers, and never resolve an interface question from a
     PDF listing when the registry or a fixture answers it.
  5. Keep the negative acceptance suite of Section 3.1 passing at every step: each of its fixtures
     is a small change that must make a successful result fail with a precise status.
  6. Return reproducible commands, structured results, replay evidence, resource records, the
     manifest claims covered and the remaining unsupported surface. Performance claims need
     measurements with unchanged semantics and arithmetic.

1     Implementation contract
1.1    Authority and scope
The specification is authoritative for semantics and the registry for interfaces. When an example,
an optimization or a host convenience conflicts with either, keep the semantics and the registry
and report the conflict. Never weaken a claim to make a fixture pass. No MeTTaDinC
implementation exists yet. The target is a reflective MeTTa sublanguage hosted first in Cetta,
with a portable semantic core that does not depend on a particular evaluator’s rewrite order.
Unrestricted MeTTa evaluation, neural training, global probabilistic inference, a general theorem
prover and the whole of Hyperseed are outside the first release.

1.2    Semantic invariants
Types and result schemas must keep the following distinctions visible.
    1. Claim kinds are distinct types: current adequacy, update compatibility, behavioral (bisim-
       ulation) adequacy, trace adequacy, simulation, exact induction, approximate induction
       and linear realization. Evidence for one never satisfies a consumer of another without a
       registered theorem; in particular a positive behavioral defect does not refute trace equality.
    2. Observation equality is Literal or Observer. A zero current defect under a non-separated
       value tolerance yields decoders into the zero-distance quotient only, and the result says so.
    3. A measurement (Measure*, Defects) is Checked when its interval is computed to the
       requested precision, whatever the value. A check (Check*) compares the interval with
       Within, whose default is 0. Output projects only from Checked results.
    4. InduceExact requires current adequacy and update compatibility with defect zero, and
       literal congruence of the code fibers, checked on code values whatever the code tolerance
       (claims C01–C03); it returns a quotient arrow. InduceApprox returns a representative
       machine, its section (default Center), radius, arrow defect and a priori bound.
    5. The horizon (Steps h) covers the initial observation and h transitions; its tolerance is
       Φh+1 (1).
    6. A transition law, a tolerance, a checked transfer and a host result bag are different types.
       A bag becomes a set, multiset or law only under the interpretation the interface declares;
       a transfer becomes a kernel only through the registered KernelOf construction.
    7. Arrow kinds have distinct types and registered composition laws: functions for quo-
       tient arrows and homomorphisms, additive defects for graded arrows and transfers,
       (λL λK , ρL λK + λL ρK ) for linear arrows, (L2 L1 , L2 η1 + η2 ) for affine contracts. Composing
       across kinds without a registered conversion is InvalidInput.
    8. A signed linear realization is not a machine. A replayed positive candidate bounds the
       positive dimension from above only.
    9. Kernel hives and transfer hives are different types with different coherence claims.
 10. A symbolic carrier is admitted only with its obligations discharged; type-checking its
     terms is not admission.
 11. A prior-dependent averaged model is an aggregate, not a quotient.
 12. Probabilities, tolerances and defects, p-bit pairs, report availability, error bounds, operator
     norms and costs never convert implicitly; an estimate becomes PLN evidence only by a
     conversion that preserves its estimand and dependence assumptions (Section 1.11).

 13. Exact claims are about admitted models; population claims need their own evidence and
     status.
 14. Shared and fresh reads of random or nondeterministic variables are declared, never inferred.
 15. Unmeasured correspondences in a hive are marked, never filled with zero.
 16. Every result carries its binding: module digest and subject names, source and target model
     identities, the checked interface with its value tolerances, and its scope (initial states,
     reachable-state scope, horizon, discount, policy class). Every operation that consumes
     a result validates the binding first, and a mismatch is InvalidInput naming the field, in
     every release.
 17. One assurance policy assigns every status: Checked only on the grounds Exact and
     Replayed, Refuted only on a replayed Witness, Conditional on (TrustedBackend solver
     version logic obligation-digest) for an unreplayed backend answer, with agreed_by
     recorded as evidence, on (Assumption name digest) for an assumption the source de-
     clares, and on (EstimatedPremise result-digest delta) for a premise that is an
     estimate; derived results inherit the union of their premises’ assumptions, and consumers
     accept only what their Accepts declaration lists.
 18. A distance value enters a result only through the registered certificate kinds, whatever
     algorithm computed it, and an exact measurement needs a lower and an upper certificate
     that meet; when the distance is a supremum that no registered certificate attains, the
     answer is Unknown with the interval. Trace-event and policy-tree tests are undiscounted
     probabilities and bound a behavioral distance at discount one only. On a stochastic
     machine a trace refutation over observation-based policies needs a policy tree; a word
     witness never certifies it.
Five regression cases protect these invariants from the start, each with its manifest claims.
First, states 0, 1, 2 with constant observations, encoding {0, 1} | {2} and update 0 7→ 0, 1 7→ 2,
2 7→ 2: the behavioral defect is zero while the update defect is one (H09, H10). Second, the
posterior summary of the receipt memory: it is not compatible with the union merge, and a
merge of posteriors as independent evidence double counts shared receipts (P10–P13). Third,
the forty-bit zero machine: a sampled relevance screen drops the tail bits, and the resulting
four-class encoding has behavioral defect one (F07). Fourth, the adversarial zero-tail candidate,
which passes every local check and fails coverage (F05). Fifth, for the first stochastic milestone,
the seven-state chain, where the behavioral check is refuted by a modal test while the trace
check passes (S03, S05).

1.3   Registry-driven handoff
The registry fixes, for every declaration head, its positional arguments, fields, field kinds and
which fields are required or repeatable; for every request, its library, positional arguments, keyed
arguments with kinds and defaults, result type, statuses beyond the base statuses, supported
dynamics and carrier backends, and the dynamics it supports in the first release; for every result
type, its fields; and the first-release capability manifest. Build the frontend from it:
   • generate, or drive from tables, the declaration parser, the argument checker and the result
     schemas, so that a registry change propagates mechanically;
   • give every request the base statuses Conditional, Unknown, Unsupported and InvalidInput
     in addition to its registered ones;
   • apply registered defaults at admission and record them in the claim, so that
     (CheckBehavioral R) and (CheckBehavioral R (Within 0) (Discount 1) (Horizon

       AllFiniteWords)) have the same identity;
  • answer Unsupported, never InvalidInput, for a well-formed request outside the running
    release’s manifest whose premises pass the binding rules, and InvalidInput for a malformed
    request or one whose premises fail them;
  • treat a method declared in a module as a request whose result type is its declared Returns

The checker check_fixtures.py is the reference reading of the registry for static questions:
an implementation’s admission must accept every fixture module it accepts and reject the
mutations it rejects (Section 3.9).
The first-release manifest covers deterministic dynamics, crisp and Łukasiewicz values,
enumerated and symbolic carriers with the BitVectors primitives, the core requests and the
GradedKernels library: BehavioralTolerance, Bracket, CheckAbstractionMap,
CheckBehavioral, CheckBlockPartition, CheckNow, CheckTrace, CheckTransitive,
CheckUpdates, Defects, Delta, InduceApprox, InduceExact, MeasureBehavioral,
MeasureNow, MeasureTrace, MeasureUpdates, MinimizeForQueries, PathClosure, Refine,
SamePartition, Then, Threshold, WeakestWithin (24 requests, generated from the registry).

    Witnesses are returned in terms of original carrier elements, never internal identifiers.
Partitions are compared as equivalence relations, never by block labels; canonical block order is
by least source element. Any change to an observation, value tolerance, update set, arithmetic
algebra, cost model, read annotation, gauge or evidence convention creates a new interface
identity. Canonical serialization respects lexical binding and alpha-equivalence and never
depends on pointers, arena order or a live mutable space.

1.6   Results, projections and status rules
Every result uses the envelope of the specification, with Value fields fixed by the request’s
registered result type. A user-authored atom headed Checked is data. (Output R Value)
returns the whole payload and (Output R F) a registered top-level field, where R is a derivation
name or a result variable bound by LetResult; projection from a result that is not Checked
yields a dependency diagnostic. Claims, bindings, scopes and defect intervals serialize as
(Claim (Kind Behavioral) (Within 0) (Equality Literal))
(Binding (Module "sha256:...") (Subject PosteriorOnly) (Machine Memory)
         (Interface (Digest "...")))
(Scope (Init (All)) (States (All)) (Horizon AllFiniteWords) (Discount 1))
(Defect (Lower (Rat 3 20) (Certificate (WordWitness ...)))
        (Upper (Rat 3 20) (Certificate (Prefixpoint ...))))
(Assumptions) (Assurance Replayed)

A result whose verdict came from an SMT solver without a replayed proof carries instead
(Assumptions (TrustedBackend cvc5 1.4.2 QF_LRA "sha256:...")), its evidence lists any
agreeing backend under agreed_by, and its status is Conditional. A measurement with
(Precision p) is Checked when u − ℓ ≤ p and Unknown otherwise. A check with bound
e is Checked when u ≤ e, Refuted when ℓ > e with the lower-bound certificate as Witness,
and Unknown otherwise. A malformed probability row is InvalidInput, never a refutation; an
interrupted implemented search is Unknown; an operation outside the manifest is Unsupported;
a failed prerequisite produces a dependency diagnostic naming it.

Obligations. For a carrier predicate C, block predicates Bi , representatives ri and a successor map

membership (C(ri ) ∧ Bi (ri )), constancy of every query on every block, stability (C ∧ Bi ⇒

candidate of fixture forty_bits.metta must be refuted on coverage with witness word 4 (claim

it by translation validation: for widths 3 to 12 of every symbolic fixture, decide each obligation

1.9    Default algorithms and their scope
With n states, m transitions and exact arithmetic costs counted separately:
   • Crisp current and update checks, those of a representation whose code tolerance is the
     discrete equality, are functional-dependency tests—does the code determine each query,
     does it determine each successor’s code—implemented as hash group-bys with exact

                                                 11
MeTTaDinC                                      Coding-agent implementation guide, 4 November 2026


      comparison, linear in n plus m. Under a two-valued metric code tolerance the same group-
      bys run on the classes of the tolerance, and InduceExact adds the literal-congruence
      group-by on the code values.
   • Behavioral partition: Hopcroft or Paige–Tarjan refinement in O(m log n) [4, 5]; for de-
     terministic machines, a splitting tree with minimal separating sequences [6]; for other
     functors, characteristic formulas in shared form [15].
   • Crisp behavioral check: compute Pbeh , then test the dependency “code determines behav-
     ioral class”. A failing group yields a witness pair, separated by the test at their lowest
     common ancestor. The pair-graph search of the specification’s definitions is the reference
     engine only; it needs Θ(n2 ) memory.
   • Stochastic lumping in O(m log n) [7, 8], with exact sums over explicit nonzero entries.
   • Graded distances: for deterministic machines, shortest paths in the pair graph restricted
     to the pairs a request needs; for labelled Markov chains with one transition function, exact
     polynomial-time computation, with policy iteration or on-the-fly algorithms in practice
     [9, 10, 11]; for several actions, exact value iteration for lower bounds and couplings for
     upper bounds, reported as an interval with no complexity claim.
   • Trace equivalence and linear realizations: Krylov iteration over the alphabet of action–
     observation letters with fraction-free elimination [12, 13]; quantitative trace discrepancy
     by exact enumeration through a declared horizon, or as an interval bounded above by a
     behavioral certificate at discount one.
   • Nondeterminism: bisimulation by relational refinement, simulation preorders in O(mn)
     [14], distinguishing formulas as in [15].
   • Symbolic refinement: signature refinement over decision diagrams as in Sigref and Storm
     [16, 17], preceded by a cone-of-influence pass and, when declared, reachability.
   • Closure: max–Łukasiewicz Floyd–Warshall in O(n3 ).
   • Frontier search: exhaustive over partitions for small carriers; heuristic otherwise, with
     optimality reported Unknown.
Hash collisions are resolved by exact comparison. Rationals are canonical (positive denominator,
reduced, normalized zero); finite-field values are reduced modulo the declared prime.
    An algorithm that computes a distance exactly still has to hand replay a certificate for each
end of the interval. Value iteration from zero yields horizon distances, which are lower bounds
certified by tests of the same depth, and over all finite words they can approach the distance
without reaching it (claim U01). At discount below one, the optimal dual potentials of the
Kantorovich programs at the computed fixed point give a DualPostfixpoint that closes the
interval (U04); at discount one no lower certificate other than tests is registered, so a Precision-0
request whose tests stop short of the upper certificate returns Unknown with the interval, even
on a chain with one transition function where the polynomial-time algorithms find the value.
Through a declared horizon, a LayeredPrefixpoint gives the matching upper bound (U02).
Over observation-based policies the trace defect through a horizon is computed by enumerating
deterministic policy trees, which suffice because a randomized policy separates no more; a
maximizing tree, with the event on which the two laws differ most, is the PolicyTreeWitness
(O03, O04). Literal congruence is one more group-by: the code value of each state determines
the code values of its successors.

1.10    Resources and incrementality
Every budget names its units: pair expansions, signature computations, decision-diagram nodes,
SAT conflicts, LP pivots, arithmetic bit operations, wall time or memory. A horizon is part of a
claim and a budget is not; exhausting a budget yields Unknown with a record of completed
work. Host evaluation fuel is never a horizon.
    Certificates are cached by the semantic digests of their dependencies. Interface changes
reuse them only through the transport rules of the specification, which distinguish universal
upper bounds, witnesses, exact values, optimality claims and measure-dependent results; each
reuse is recorded as a derivation step citing its rule, and the step validates the certificate’s
binding first. No rule moves a certificate to another machine, simulation target, stream or
snapshot. A result bound to a view keeps the view’s queries when the item machine gains a
query, and gives the new query’s consumer no coverage. Adding a query resumes refinement
from Pbeh ∩ ker o; adding an action resumes from Pbeh ; removing queries or actions transports
upper bounds and downgrades coarseness to sufficiency. Restricting to a forward-closed subset
transports upper bounds, keeps a witness only if its pair lies in the subset, and recomputes exact
values, optimality and measure-dependent results (claims H03, H04). Recompiling a module
changes its artifact digest, not its semantic digest, and invalidates nothing.

1.11    Estimates and their conversions
An Estimated result carries, in the envelope’s Estimate field, its estimand, estimator, sampling
protocol, sample size, error bound, failure probability, dependence assumptions and combination
rule, and also its population (the units the stream samples), its selection rule (which units
become rows, and when), the digest of the policy version under which the rows were produced,
and the estimand as a function of that population. Reuse under another policy version needs
a declared transport argument, for instance pointwise monotone labels on a fixed population,
or a new estimate; a selection rule that depends on the policy blocks transport. A stream
whose declared digest does not match its file is InvalidInput before any count is taken. A result
derived from an estimate keeps the Estimate field and is Conditional on (EstimatedPremise
result-digest delta), so only a consumer that accepts Estimated results can use it. The
ωPLN adapter converts an estimate to evidence counts only when it is a proportion over
independent observations of the same estimand; a U-statistic of order two converts to an interval
truth value, or to counts of effective size ⌊n/2⌋ for a Hoeffding-type consumer; an anytime-valid
or sequentially selected estimate converts to an interval truth value at its stopping time and
never to counts; an estimate from dependent samples carries its dependence assumptions.
Converting an Estimated result into an exact channel is a negative gate.

2.3   Admission
Implement source admission before any domain algorithm. It consumes held syntax, resolves a
complete DC.Module, and returns an immutable admitted module or a structured failure; dc.run
is a wrapper around it. A proposed private entry is __cetta_lib_dcalc_admit. Establish
raw-data treatment of its arguments through grounded_dispatch_accepts_data_arg or an
equivalent typed holding wrapper, without broadening data treatment for other native operations
and without adding the service to the type-pure list.
   The first admission tests install hostile host equations for names such as Map, Body and a
module-local function, and a held expression containing an I/O or state-mutating operator.
Loading the module must execute none of them. Phases, in order:
  1. parse with source locations, collecting declarations without executing embedded requests;
  2. check every declaration and request against the registry: heads, fields, argument kinds,
     required arguments, defaults; assign module-local identifiers; reject duplicates and unknown
     references, and never resolve a name against the surrounding space;
  3. check the profile coordinates against the capability manifest and the effect and type
     signatures of imported primitives;
  4. check binders, expression types and dependency edges: linear case patterns, one lexical
     argument per Body, an acyclic map-call graph, no derivation cycles;
  5. resolve carrier elements at their element types (symbols in symbol-typed carriers, constants
     otherwise) and reject duplicates under typed equality; compute separation of each value
     tolerance;
  6. for enumerated carriers, materialize maps and kernels, rejecting missing or overlapping
     cases (even agreeing ones), out-of-carrier values, invalid rationals, unnormalized rows
     and floating-point literals in exact positions; for symbolic carriers, discharge totality,
     exclusivity and closure through the obligation generator and the proof pipeline, or by a
     cited construction rule;
  7. freeze the IR and its digest, and execute requests against that snapshot.
Never apply host nondeterministic rewriting to a deterministic map. Two host alternatives are
neither a law nor a legal map; a nondeterministic map is admitted only through Choice with a
declared bag interpretation.

2.4   Ownership and persistence
Cetta atoms are arena-allocated with recorded arena identities and reset epochs. Never keep a
borrowed pointer from a request’s scratch arena in a retained module, cache entry or certificate;
copy semantic values into storage whose lifetime covers every consumer, including transitive
children. Native resources (decision-diagram managers, solver instances) have one owner and
a destructor, and admission defines what happens when a handle closes or a session ends.
Three identities stay separate: the semantic module digest, the compiled artifact digest and
the runtime handle. Shared admitted modules are immutable; scratch state is thread-local or

3     Milestones, fixtures and acceptance evidence
Milestones describe capability and evidence, not calendar time. The first useful release is
M0–M3: strict certificate boundaries, the full frontend, the graded deterministic core and the
symbolic backend. Each work package ends with the manifest claims it covers, reproducible
commands, structured results, negative cases, a replay run and a statement of the remaining
unsupported surface. A claim is covered when the implementation returns its required status and
values with replayable evidence; claims outside the running release must return Unsupported.

3.1    M0: strict certificate boundaries
The first milestone is a small implementation whose certificate boundaries are strict. It answers
few requests, and it keeps its guarantees under small adversarial changes of its inputs: a premise
about the wrong machine, a stream whose content changed, a verdict that rests on a solver
answer nobody replayed, a code tolerance that hides a literal failure. The fixtures of the package
and of the application bundles already exercise more forms than a first implementation can
make reliable, so M0 makes the boundaries strict before any breadth is added. Every later
milestone keeps them, and keeps the suite below passing.
    M0 delivers one mechanism for each boundary, or fixes its interface where a later milestone
builds it.

       identities, the checked interface with its value tolerances, and the scope with initial states,

       before any consuming operation uses a premise: Then and transfer composition, safety
       transfer along a simulation, lifting to a keyed store, rebuilds, stream and snapshot reads,
       and gates. The registry’s binding rules run at admission, so a mismatch is InvalidInput
       naming the field in every release, also for a request that is otherwise Unsupported, and
       wrong-store lifting and wrong-target safety transfer are rejected before any proof transfer
       begins.

schema round-trips and stale dependencies separately from mathematical obligations.

3.10    Handoff and definition of done
Each handoff names the specification date, the registry digest, the Cetta commit, the profile
coordinates, owned files, dependencies and the manifest claims covered. A completed package
includes:
   1. implemented source forms and request signatures, with unsupported forms listed;
   2. the manifest claims covered, with their structured results and replay evidence;
