## Meaning: this needs a normal review

The conflicts were not limited to shared test and report files: C source conflicted too (model.c, model.h, ops_req.c),
because both M0 changes had added their own copy of the dc_skip_why mechanism, and the order asked for them to be merged
into one. What changes beyond pure conflict resolution:

1. **Capacity.** The skipwhy table is 32 x 256 bytes (on main it was 8 x 192 for Bool-observe reasons). Only the capacity changes.
2. **Reason prefix.** A Representation over a machine that was skipped for a type-form reason now reports "Machine M: <why>"
   (main's format) instead of "<why>" alone (PR 35's format). The typeform gate checks reasons by substring and still
   passes; its output lines are identical.
3. **Emergent reason on doc04 TaskResume rows 45-48.** Status (Unsupported) and class (GAP) are unchanged. The reason
   text now ends with ": Machine Resume: Observe needs-revalidation: Map needs-revalidation: Cases row 0 uses an operator
   outside the M0 fragment". On main, the machine Resume was first skipped by a type-form map, which recorded no reason.
   With type-form maps lowered, the first blocker is the Bool Observe map's Eq/And body (c), and main's Bool-observe
   code records that reason. No code was written for this. It appears in 3 copies of the doc04 bundle (bytediff.txt)
   and in out/mg_*.tsv and the doc04 table (commit 1cdc10d).
