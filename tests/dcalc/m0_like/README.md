# m0_like: (Machine M (States S) (Like N)) in the Crisp M0 lowering (t-2026-11-23-mettadinc-m0-like-machines)

Probe X2 is `tests/dcalc/examples_e2e/repro/m0_blocker_d_like.metta` (D1), the form TaskResume uses:
`(Machine Resume (States Live) (Like Restart))` (doc04 memory_goals.metta:424).

## What the form means, and where that is written

- `Like` is a keyed field of `Machine` in `registry/mettadinc_registry.json` (type `ref:Machine`, optional), with the
  doc "the observe and action entries of another machine; States may differ (a scope)". It comes from the ex2 bundle
  patch, adopted into the registry before M0 (`registry/SOURCES.md`). Spec 5.1 (txt l.1659-1662) makes the registry
  the normative definition of every declaration field. doc04 Table 14 (l.3805-3806) lists it: "TaskResume uses Like only".
- Ben's reference evaluator `docs/e0/docs/04_omega_memory_goals_part1/validation_bundle/mg_eval.py` (`entry_exprs`,
  l.350-357) resolves it the same way: the Like machine's entries are N's entries.
- "A scope": S may be a Reach or Subset carrier of N's state carrier. Maps are then used on S by restriction (spec 5.3
  "Reachability scopes", l.1810-1818; Table 7 "Restrict to a forward-closed subset"), and an action whose value leaves S
  is InvalidInput (5.3 admission obligations, l.1785: outputs stay in the carrier).

Lowering (`src/dcalc/model.c`, `admit_like`): M gets exactly N's `(Observe label map)` and `(Action label map)`
entries, in N's declaration order, each admitted on M's own States as if it were written there. A Like of a Like
machine follows the chain. So a Like machine answers byte-for-byte as the same machine written out, which the gate
checks.

Malformed (InvalidInput): `(Like)` with no name or with two values, a non-name value, a repeated Like field (spec 5.1
l.1752-1753; admit.c refuses these four first, from the registry), N undeclared, N = M, or a copied entry that fails on S
(the action leaves S, or the map does not start at S). The reason says the entry came from N by field Like.

Outside this lowering (Unsupported, the reason names Like): a non-Crisp module; N outside the fragment; N declared after
M (the M0 lowering reads Like in declaration order); Like together with M's own Observe/Action/Merge or other fields
(the registry text does not say how they combine, and the reference evaluator silently drops M's own entries); N with
Merge entries (the registry text names only observe and action entries). The reason text reaches the request through a
per-declaration reason table (`dc_skip_why`), set only for these Like cases, so no other reason changes.

## The gate (`run_m0_like.py`, both modes)

Fixtures (`fixtures/`):

- `like_gates.metta`. A = {a b c d}; step swaps a<->b and c<->d; obs: a,c -> o1 and b,d -> o2; Live = (Reach Base
  (From a)) = {a b}; enc1: a k1, b k2, c k1, d k1; enc2: a k1, b k1, c k2, d k2.
  Worked by hand (least pair in carrier order, then shortest word):
  - On all of A (LB: Base itself; LA: `(Machine Copy (States A) (Like Base))`):
    CheckNow R1 Refuted, pair (a d): equal code k1, obs o1 vs o2 ((a b) has codes k1/k2; (a c) agrees on obs).
    CheckUpdates R1 Refuted, pair (a c), action step: codes k1 k1, but step a = b (k2) and step c = d (k1).
    CheckBehavioral R1 Refuted, pair (a d), empty word. CheckNow R2 and CheckBehavioral R2 Refuted, pair (a b) (k1, o1 vs o2).
  - On the scope Live = {a b} (LS: `(Machine Scoped (States Live) (Like Base))`; LW: Scoped written out; LC: a Like of a Like):
    enc1 is injective on {a b}, so CheckNow, CheckUpdates and CheckBehavioral R1 are Checked; R2 still Refuted with
    pair (a b); MinimizeForQueries Scoped gives the blocks {a} {b}.
  The difference between LB and LS (Refuted vs Checked on R1) is the scope: a lowering that ignored States would answer
  LS as LB. Each answer is also checked against the reference evaluator run on the same file, and LS/LC/LA must answer
  byte-for-byte as LW/LS/LB.
- `taskresume_like.metta`, generated by `desugar_taskresume.py` (checked by the gate): doc04's TaskResume with every map
  written as a Table computed by the reference evaluator from memory_goals.metta, Bool as an Enum carrier YN, the
  checkpoint code as a declared Product, so that `(Machine Resume (States Live) (Like Restart))` is the only form under
  test (TRL), with a written-out control (TRW). The five requests give doc04's answers (s7.3 l.1518-1524): CheckNow
  NoReadSets Checked; CheckUpdates NoReadSets Refuted, pair (valid valid r1 current)/(valid valid r2 current), action
  withdraw1; CheckBehavioral NoReadSets Refuted, word withdraw1, query needs-revalidation; CheckBehavioral ReadSets Checked;
  ResumeMemory 11 classes on 12 states. Witnesses and blocks are checked against the reference evaluator on the original
  module.
- `like_invalid.metta`: LN1-LN7 InvalidInput (undeclared N; N = M; two values; repeated field; Like onto a Subset that
  step leaves; Like onto an unrelated carrier; a non-name value).
- `like_unsupported.metta`: LU1-LU4 Unsupported with a reason naming Like.

On the base binary (8ae0fa7) the gate fails 118 of 173 checks; the four InvalidInput cases the registry admission
already caught (LN1, LN3, LN4, LN7) pass there. Two meaning mutants of `admit_like` (drop the Observe entries; ignore
the scope and use N's States) fail 56 and 46 checks.

## Other tools

  or (a) (To Bool) Observe maps block all five TaskResume rows; (b) a type-form To or the Body map on
  checkpoint-with-reads block row 48 (CheckBehavioral ReadSets) only.
